# Codex 실행 프롬프트 · 수동 제어 1단계

아래 프롬프트는 함께 제공한 [작업지시서](WORK_ORDER.md)를 기준으로 저장소 루트에서 사용한다.

```text
/goal
노션 근거를 반영한 manual_station/WORK_ORDER.md에 따라
오프라인 자율 물류 지게차의 첫 단계 수동 제어 소프트웨어를 준비하라.
완료 상태는 SOFTWARE_READY / HARDWARE_PENDING이다.

반드시 지시서를 먼저 읽고 현재 파일과 기존 팀 코드를 조사한다.
입고·식별·지도·집기·운반·하역·재고·안전의 전체 추적표를 유지하되
이번 구현은 수동 조작, 상태 표시, 정지, 기록, 후속 확장 계약에 집중한다.

금지: 실제 GPIO/모터/리프트/센서 취득 실행, 기존 제어 프로그램 실행,
실물 확인 플래그 임의 변경, 핀 충돌의 추측 해결, 자동 시작 서비스,
공개 네트워크 노출, 타 팀원의 프로세스 강제 종료, 계정 인증 복사.

기존 원본을 보존하고 독립 manual_station 패키지를 만든다.
기본은 mock이며 import/시작/페이지 로드/ARM만으로 움직이지 않는다.
real은 명시 실행+검증된 설정+사용자 제어권+ARM+새 조작 입력이 모두 필요하다.
한국어 웹 패널과 사용자용 실행 스크립트, 배선 템플릿을 제공한다.
바퀴 개별/전후좌우·출력조정·STOP·래치 ESTOP·RESET·리프트 계약을 구현한다.
확인되지 않은 좌우/리프트/센서는 차단 사유를 표시하며 정상값을 만들지 않는다.
원격 입력의 만료·순서·재접속, 연속시간, 방향전환 정지, 단일 출력 소유를 지킨다.
실물 backend의 PWM은 유한 길이이며 명령 만료보다 뒤로 큐를 누적하지 않는다.
입력루프와 별도의 만료 감시를 두고 예외·로그 실패에는 출력 OFF와 고장을 남긴다.
SQLite 기록의 명령/관찰을 실제 운송 성공과 구분한다.

모의 backend와 가짜 GPIO로 위험 경계를 검증한다.
테스트는 모터핀에 접근하지 않아야 한다. 웹은 mock에서만 검증한다.
파이에는 /srv/jongsul/forklift/manual_station 아래 새 파일만 배치한다.
실물 모드나 장치 취득 서비스를 실행하지 말고 사용자가 실행할 명령을 남긴다.
기존 GPIO 배선·극성·리프트 리미트 등 현장 확인이 없으면 HARDWARE_PENDING을 유지한다.
테스트 결과·노션 문서·실행법을 갱신하고 실제 구동하지 않았음을 명시한다.
완료 기준을 충족한 소프트웨어 단계까지만 목표를 완료로 표시한다.
```

## 후속 /goal 범위

첫 현장 수동 시험 결과를 받은 뒤 센서 취득·지도/영상·하단 한 건 물류 작업을 각각 별도 목표로 진행한다. 이 프롬프트만으로 무인 운행이나 실물 출력 권한이 추가되지 않는다.
